# 无头调用执行命令的核验

日期 2026-10-15
状态 已完成
原始证据 `RECORD/probe_bash.json` 与 `RECORD/probe_bash/` 下的六份 stream 记录
核验脚本 `harness/probe_bash.py`

## 一、为什么先做这一条

题目要求比较代码智能体在能运行测试与不能运行测试两种条件下的反馈效应。这一设计的前提是，无人值守的 `claude -p` 调用里模型真能执行测试命令并拿到输出。此前没有任何证据支持这条前提，只有相反方向的一次探测，即不给 Bash 时模型不会调用 Bash。前提若不成立，这一整个因子就是空的，所以先把它测实。

## 二、方法

一次性工作区建在临时目录，与项目树分离。工作区内放一个带缺陷的 `median` 实现与两条测试，奇数长度一条通过，偶数长度一条失败，构成最小可判定的失败态。虚拟环境由 `uv` 建立并装入 pytest。子进程环境按白名单注入，鉴权串只从 `settings.json` 读出后注入，不打印也不写入任何产物。调用统一走原生 `claude.exe`，模型 `deepseek-v4-pro`，`--effort high`，`--safe-mode`，输出为 `stream-json`，墙钟超时 180 秒。每组配置调用一次，除权限相关参数外其余全同。

## 三、六组结果

| 组 | 与基准的差别 | 发出的命令 | 结果 |
|---|---|---|---|
| A | 仅把 Bash 放进 `--tools`，权限模式 `acceptEdits` | `python -m pytest` | 被拒 |
| B | 追加 `--allowedTools "Bash(python -m pytest:*)"` | `python -m pytest` | 执行，回传完整输出 |
| C | 同 B，提示改为依次发两条命令 | `echo`，`pytest` | 两条都执行 |
| D | 规则改写作 `Bash(python -m pytest *)` | 同上 | 两条都执行 |
| E | 规则改写作 `Bash(python:*)` | 同上 | 两条都执行 |
| F | 权限模式改为 `manual`，规则同 B | 同上 | 两条都执行 |

A 组的拒绝原文是一句权限提示，大意是此命令需要批准。模型随后回复请用户在权限提示中批准，它无法自行运行。B 组回传的正文含 `collected 2 items`、`test_calc.py .F` 与失败断言详情，是真实的 pytest 输出。

## 四、三条影响设计的发现

### 1. 只把 Bash 放进工具列表不足以执行命令

`--tools` 管的是工具可用性，不是权限。`--permission-mode acceptEdits` 只自动放行文件编辑，命令调用仍走审批，而无头模式弹不出审批，于是一律被拒。不追加 `--allowedTools` 时，`can_run` 臂会静默退化成 `no_run`，而报告仍会声称两臂在测试可运行性上不同。这是本次核验最主要的结果。

### 2. 命令级限制无法实现，Bash 一旦放开就是全面放开

C 至 F 四组都要求模型额外执行一条 `echo`，四种组合下 `echo` 全部被执行。改变规则写法与权限模式均无效。结论是只要给出任何一条 Bash 允许规则，整个 Bash 工具即被放开，规则括号里的内容不参与命令级匹配。

据此，`can_run` 臂无法限制为只跑测试命令，只能接受无约束的 shell 权限。原设想中限制为测试命令的写法应当删除，改为如实统计并报告非测试类 Bash 调用的占比，作为该臂的协变量。这一点须同时写进设计与局限两节。

### 3. `is_error` 不能作为被拒的判据

pytest 因测试失败而退出码非零时，`tool_result` 的 `is_error` 同样为真。此时命令是执行成功的。初版判定函数按 `is_error` 判定，把 B 组这条成功执行误判成被拒，直到逐条读取结果正文才发现。

正确做法是只看正文。被拒的正文是一句权限提示，执行的正文含测试输出。后续脚手架里凡涉及失败信息提取与状态判定的地方，一律以正文内容判定，禁止使用 `is_error`。

## 五、另记一处环境噪声

Git Bash 会读取 `~/.bashrc`，其中引用了本机不存在的 Windows 版 Anaconda 路径，命令结果里因此多出一行 `conda.sh` 找不到的报错。本次六组中两组出现，不稳定。

若判分所用的失败信息由脚手架自己执行测试产生，则不受其影响。但 `can_run` 臂里模型看到的就是这份带噪声的输出，报告需就此说明。

## 六、成本

本次六组共 0.2575 美元，单组介于 0.03 与 0.05 之间，`num_turns` 为 2 至 3。连同前两次试跑，本项核验合计约 0.4 美元、11 次调用。成本仍不构成约束。

## 七、遗留

1. `bypassPermissions` 未测。它会关闭审批闸门并放开任意命令，是否使用须单独确认后再定，本次未纳入。
2. 工作区根目录尚未确定，本次落在一处临时目录，用完即弃。
3. 未测模型在需要改文件时是否绕开 Edit 与 Write 而改用 Bash 写文件。这决定 `can_run` 臂的工具调用统计口径与 `L_model` 的可比性，需要单独补一条核验。
