## 一、要做什么

题目 20 考察用户负面反馈对代码智能体修复行为与过度修改的影响。做法是造不少于二十个小型修复任务，先让模型修一轮，失败后从同一失败状态分出五个独立分支，各注入一种反馈再修第二轮，比较修复成功率、回归错误率与修改规模。

要回答五个问题。

1. 负面反馈是否提高修复成功率。
2. 负面反馈是否增加修改规模或引入回归错误。
3. 加入方法指引是否比单纯的负面反馈更有效。
4. 模型能否运行测试，是否改变反馈的作用。
5. 真实使用代码智能体时，怎样的反馈最有利于修正错误。

交付物为任务包、脚手架、运行产物、指标表与图，以及最后的报告与演示文稿。

## 二、已定的设计约束

以下十四条为已定项，不再作为待议项。前九条由阶段 0 的两次核验得出，第十、十一条由阶段一得出，第十二、十三条由难度探测得出，第十四条由来源一的小样本校准得出。第十二条在难度探测后按第八节的取舍改写，又在来源一校准后按 `LOG/06` 的结论收紧失败信息的粒度。

1. `can_run` 臂的参数组合固定为工具列表含 Bash 并追加一条 Bash 允许规则。命令级限制已证不可实现，该臂接受无约束的 shell 权限，非测试类 Bash 调用占比作为协变量如实报告，不得声称该臂限制了命令。
2. 失败信息单一来源。由脚手架自己执行测试生成一次，逐字节内嵌进五份提示词，并断言渲染后只差一行。
3. 状态判定一律以工具结果的正文内容为准，禁止使用 `is_error`。命令因测试失败而退出码非零时该字段同样为真。
4. 工具调用统计分三列，已执行、被拒、未启用。`no_run` 臂里模型仍可能尝试调用 Bash，未启用的尝试不得计入有效调用。
5. 首轮提示词保持中性，不含最小化要求，最小化只出现在方法指引类条件里。
6. 造题时让最小补丁落在三到五行。补丁过小时比值会被单行写法差异放大，核验中已见等价修复使比值达到两倍以上。
7. 判分用可见测试与隐藏测试的并集，首轮模型只看到可见测试的失败信息，第二轮另报外部检查的未通过项数，两者通过率之差记为 `overfit_rate`。
8. 一轮等于一次 `claude -p` 调用，即一个用户回合。CLI 无参数可限迭代轮数，故由墙钟、工具白名单与提示词共同约束，该定义原样写进报告。墙钟取六百秒，口径与超时处理见第十四条。
9. 工作区位于 ASCII 路径且不在项目树内，工作区仓库显式设 `core.autocrlf=false`，一切产物写出显式指定换行为 LF。
10. 脚手架执行 pytest 时子进程环境必须含 `PYTHONUTF8=1` 与 `PYTHONIOENCODING=utf-8`。缺任一项时中文报错在管道里被写成替换字符，进入提示词的失败信息即为乱码。该条由阶段一实测得出。
11. 不得隐瞒工作区内可读的失败信息。可见测试文件位于工作区内，模型用读取工具即可复原全部期望值，收紧其失败信息既无效又损害条件间的可比性。隐藏测试位于工作区外，模型无法读取，其断言是否进入提示词属于任务结构而非隐瞒，口径见第十二条。难度只能来自任务结构。
12. 分支判据与判分判据统一为可见与隐藏的并集，两者之差记 `overfit_rate`。并集未全绿即视为首轮失败，进入分支。第二轮的失败信息只报未通过的外部检查项数，不交断言原文与期望值。隐藏测试始终在工作区外，其内容不进入任何一轮的模型视野。五个条件拿到的失败信息仍逐字节相同。该条原为可见测试判分支、并集判分，因难度探测确认首轮失败率无法由任务内部变量抬起，先改为并集判据；校准又确认交断言会使第二轮修复成功率触顶，故收紧为只报项数。
13. 一处缺陷配一条见证测试，且该条测试只断言与这处缺陷相关的量，不受其余缺陷影响。满足这一条则修好任何一部分缺陷都无法让可见测试转绿，缺陷数量才是干净的变量。该条由难度探测第二轮实测得出，违反它的任务包已废弃。
14. 一轮的墙钟为六百秒。超时记为失败，主分析按失败计；同时按截断前的工作区判分做一次敏感性分析，并单独报告超时率。超时发生在编辑之前还是之后必须逐条记录。该条由来源一校准得出，只报项数那一档一次即撞到三百秒。

## 四、任务包与实验矩阵

任务包从一个全绿的实现出发，用反向补丁注入缺陷，使参考补丁与注入补丁由构造保证互逆，不必人工维护。每个任务含干净实现与可见测试、判分用隐藏测试、注入补丁与参考补丁，以及记录缺陷类型、允许修改范围、测试命令与参考补丁规模的元数据。

任务总数二十个起步，覆盖七类缺陷，每类约三个。缺陷类型的分配与 `test_access` 的分层需要同时考虑，避免两类因素混淆。

实验矩阵为二十个任务乘两个模型，每个任务在两臂各跑一次，五个条件在首轮失败后按下述流程分出。

```
每任务每模型每重复
  首轮   从同一个起点直接修一轮，起点只跑一次
  若首轮全绿则结束，记 PASS_R1
  若首轮失败
     提交一轮结果，快照并断言五个克隆的哈希相等
     五个条件各修一轮，判分并记录
```

`test_access` 取任务内配对而非任务间分层。理由是第四条研究问题本身是交互效应，任务间设计既功效低又与任务难度混淆，而全交叉带来的调用量加倍折合不到十美元，成本不构成理由。

调用量的估算见 `02-算力与资源评估.md`。

## 五、指标口径

表 3 的五项指标照 `REQUIRE.md` 计算。三处口径需在落地前定死并写进报告。

1. 修改规模分轮记录。跨条件比较用第二轮的原始值，因为五个条件的第二轮起点逐字节相同。跨轮比较不可用，因为第二轮要做的活已经变少。同时报告两轮累计值。
2. 回归破坏给两套口径。累计口径把干净基线到终点的全部失败都算进去，贴题目的原本应通过。增量口径只算第二轮新造成的破坏，可用于条件间归因。主表用累计，附表用增量。
3. 修改文件数与修改行数一并报告，两者都由 `git diff --numstat` 取得，只统计允许修改的文件。

除表 3 外另报两项。`overfit_rate` 为可见与隐藏通过率之差。过程指标至少含超时率、首次编辑前的读取次数、编辑调用次数与非测试类 Bash 占比，前者用于排除探索时长被误读为能力差异，中两者直接对应题目所说的更谨慎地定位还是过度修改。

## 六、验收清单

阶段 4 结束后逐条核对，全为是才进入阶段 5。

1. 每个首轮 episode 都有修改前后的测试结果、补丁与原始流。
2. 每个分支点的五个克隆快照哈希完全相等，且该断言记录在产物里。
3. 五份二轮提示词渲染后只差一行，脚本断言通过。
4. 每个条件的失败文本与单一来源文件逐字节相同。
5. 三种结局各至少出现一次，即首轮通过、首轮失败而第二轮修复成功、两轮均失败。并集判据下，可见全绿而隐藏未全绿记为首轮失败，另以 `overfit` 标记区分。
6. 篡改与空改动两条异常路径被假模型触发并正确处理。
7. 报告生成幂等，删掉产物重跑后表与图的哈希一致。
8. 中断续跑通过，中止后重启无 episode 重跑，总数不变。
9. 校准表就位。首轮失败率按任务集总体计算并如实报告，逐任务只记实际结局，不要求落入区间。第二轮各条件的修复成功率落在两成到八成之间，越界任务列入重造名单。首轮校准测得逐任务结局为零或一，原因是模型在可见测试转绿处即停手，该结局本身是研究现象，不作为淘汰理由。
10. 总时长与总成本已记录，并据此给出全量预算。

## 七、风险

| 风险 | 对策 |
|---|---|
| 首轮通过率过高导致 `M_fail` 过小 | 两轮难度探测共十四次首轮全部一次通过，两个模型皆然。已排除三条路，代码规模、缺陷数量、首轮失败信息的有无，另外确认模型强弱也换不来失败样本。改用来源一后，校准六次首轮全部失败，`M_fail` 不再过小 |
| 来源一压出失败率但第二轮触顶 | 校准确认交隐藏断言时模型七十七秒一次修好，修复成功率将停在一。已定只报未通过项数，断言不进入提示词。阶段二出口以第二轮修复成功率为准，见验收清单第九条 |
| 只报项数导致修复成功率跌到地板 | 校准中模型在三百秒内自行找到隐藏规则，说明可诊断。若正式运行出现地板，按任务调整隐藏面偏差的可诊断程度，不退回交断言 |
| 超时率随难度上升 | 墙钟提高到六百秒，超时按失败计并单列超时率，另做按截断前工作区判分的敏感性分析。超时是否发生在编辑之前逐条记录 |
| 二轮样本量不足 | 主结论以风险差与区间为主，p 值为辅，且在看结果前写下 |
| 服务端模型漂移 | 同一任务的五个分支连续执行，条件顺序用固定种子打乱，记录时间戳事后检查 |
| 条件长度混淆 | 五条件内无法消除，改为预注册披露，用正交对比而非五组两两比较 |
| 两臂系统提示规模不同 | 两臂工具集不同导致输入规模相差约一倍二成，报告中不得声称两臂只差一个权限 |
| 隐藏测试泄漏 | 隐藏测试只经公开接口，不得触碰下划线开头的名字 |
| 网络路径变更 | 全部调用打同一个远端端点，跑批前后各确认一次代理模式 |

## 八、难度来源与已定取舍

十四次首轮全部一次通过，首轮失败的可能来源只剩三条。三条都要改动已定的设计，已定以来源一为主，来源二备选，来源三不采用。口径见下，约束 12 已两次按此改写。

**来源一，缺陷行为不能由可见测试唯一确定。** 模型照着可见测试做，可见全绿而隐藏未全绿。这条能给出一批首轮失败，代价是要把分支判据从可见测试改为可见与隐藏的并集，也就是改约束 12。好处是它同时把 `overfit_rate` 从零变成可估的量，而过度拟合可见测试本身就是题目关心的行为。坏处是第二轮必须给模型一点关于外部检查的提示，否则它无从知道还有未通过项，而提示的粒度会直接决定第二轮难度，须在校准中定死。

**来源二，限制每轮允许的工具调用或修改次数。** 题目第三条明确把每轮允许的工具调用或修改次数列为要固定并报告的参数。缺陷数超过额度时首轮必不全绿，失败由构造保证，与任务难度无关而只与额度有关。此时测的其实是额度下的行为差异，需要在报告里如实说明，不得包装成修复能力差异。CLI 无直接限制轮数的参数，可用 `--settings` 注入 `PreToolUse` 钩子在编辑次数超限时拒绝，代价是脚手架多一层，且钩子本身要在两臂与五条件间完全一致。

**来源三，墙钟。** 难度探测阶段实测最长五十二点六秒，距三百秒尚有五倍余量。来源一校准中只报项数那一档已在三百秒处被截断一次，说明难度一旦上升，墙钟会先于能力成为约束。因此不采用缩短墙钟制造失败的做法，改为把墙钟提高到六百秒并单独报告超时率，见约束 14。缩短墙钟仍不可取，因为超时与模型速度强相关，两个模型的耗时相差一倍以上，会把条件差异与模型差异混在一起。

**取舍，已定。** 取来源一。理由是它给出的是真实的、与过度拟合有关的首轮失败，与题目的分析要求最贴，来源二给出的是额度约束下的行为差异，可控但人为，留作备选。来源三不采用。

来源一的落地口径有三条。

1. 隐藏测试定义为工作区看不到、由用户方 CI 跑的那一部分。首轮提示词里只出现可见测试的失败输出，模型无从得知隐藏测试的存在。
2. 分支判据改为可见与隐藏的并集。并集未全绿即视为首轮失败，进入分支。这一条同时废止了原先可见全绿而隐藏未全绿记为 PASS_R1 的处理。
3. 第二轮的失败信息只报未通过的外部检查项数，不交断言原文与期望值。五个条件拿到的失败信息仍然逐字节相同。隐藏测试始终在工作区外，其内容不进入任何一轮的模型视野，这一点写进报告的方法一节。

`overfit_rate` 仍照原口径报告，即可见通过率与并集通过率之差，含义变为首轮里有多少任务是照着可见测试改对了表面而没改到实质。

来源一已由小样本校准证实能够压出首轮失败。三次任务、六次首轮全部失败，形态全部是可见全绿而隐藏未全绿，`overfit_rate` 由零变为一。校准同时发现第二轮的失败信息粒度决定实验能否成立，交断言会使修复成功率触顶，故落地口径第三改为只报项数，并新增第十四条超时口径。原始证据见 `RECORD/probe_source1/`，分析见 `LOG/06`。来源二留作备选，暂不启用。
