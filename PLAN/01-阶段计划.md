## 一、要做什么

题目 20 考察用户负面反馈对代码智能体修复行为与过度修改的影响。做法是造不少于二十个小型修复任务，先让模型修一轮，失败后从同一失败状态分出五个独立分支，各注入一种反馈再修第二轮，比较修复成功率、回归错误率与修改规模。

要回答五个问题。

1. 负面反馈是否提高修复成功率。
2. 负面反馈是否增加修改规模或引入回归错误。
3. 加入方法指引是否比单纯的负面反馈更有效。
4. 模型能否运行测试，是否改变反馈的作用。
5. 真实使用代码智能体时，怎样的反馈最有利于修正错误。

交付物为任务包、脚手架、运行产物、指标表与图，以及最后的报告与演示文稿。

## 二、已定的设计约束

以下九条由阶段 0 的两次核验直接得出，不再作为待议项。

1. `can_run` 臂的参数组合固定为工具列表含 Bash 并追加一条 Bash 允许规则。命令级限制已证不可实现，该臂接受无约束的 shell 权限，非测试类 Bash 调用占比作为协变量如实报告，不得声称该臂限制了命令。
2. 失败信息单一来源。由脚手架自己执行测试生成一次，逐字节内嵌进五份提示词，并断言渲染后只差一行。
3. 状态判定一律以工具结果的正文内容为准，禁止使用 `is_error`。命令因测试失败而退出码非零时该字段同样为真。
4. 工具调用统计分三列，已执行、被拒、未启用。`no_run` 臂里模型仍可能尝试调用 Bash，未启用的尝试不得计入有效调用。
5. 首轮提示词保持中性，不含最小化要求，最小化只出现在方法指引类条件里。
6. 造题时让最小补丁落在三到五行。补丁过小时比值会被单行写法差异放大，核验中已见等价修复使比值达到两倍以上。
7. 判分用可见测试与隐藏测试的并集，模型只看到可见测试的失败信息，两者通过率之差记为 `overfit_rate`。
8. 一轮等于一次 `claude -p` 调用，即一个用户回合。CLI 无参数可限迭代轮数，故由三百秒墙钟、工具白名单与提示词共同约束，该定义原样写进报告。
9. 工作区位于 ASCII 路径且不在项目树内，工作区仓库显式设 `core.autocrlf=false`，一切产物写出显式指定换行为 LF。

## 四、任务包与实验矩阵

任务包从一个全绿的实现出发，用反向补丁注入缺陷，使参考补丁与注入补丁由构造保证互逆，不必人工维护。每个任务含干净实现与可见测试、判分用隐藏测试、注入补丁与参考补丁，以及记录缺陷类型、允许修改范围、测试命令与参考补丁规模的元数据。

任务总数二十个起步，覆盖七类缺陷，每类约三个。缺陷类型的分配与 `test_access` 的分层需要同时考虑，避免两类因素混淆。

实验矩阵为二十个任务乘两个模型，每个任务在两臂各跑一次，五个条件在首轮失败后按下述流程分出。

```
每任务每模型每重复
  首轮   从同一个起点直接修一轮，起点只跑一次
  若首轮全绿则结束，记 PASS_R1
  若首轮失败
     提交一轮结果，快照并断言五个克隆的哈希相等
     五个条件各修一轮，判分并记录
```

`test_access` 取任务内配对而非任务间分层。理由是第四条研究问题本身是交互效应，任务间设计既功效低又与任务难度混淆，而全交叉带来的调用量加倍折合不到十美元，成本不构成理由。

调用量的估算见 `02-算力与资源评估.md`。

## 五、指标口径

表 3 的五项指标照 `REQUIRE.md` 计算。三处口径需在落地前定死并写进报告。

1. 修改规模分轮记录。跨条件比较用第二轮的原始值，因为五个条件的第二轮起点逐字节相同。跨轮比较不可用，因为第二轮要做的活已经变少。同时报告两轮累计值。
2. 回归破坏给两套口径。累计口径把干净基线到终点的全部失败都算进去，贴题目的原本应通过。增量口径只算第二轮新造成的破坏，可用于条件间归因。主表用累计，附表用增量。
3. 修改文件数与修改行数一并报告，两者都由 `git diff --numstat` 取得，只统计允许修改的文件。

除表 3 外另报两项。`overfit_rate` 为可见与隐藏通过率之差。过程指标至少含超时率、首次编辑前的读取次数、编辑调用次数与非测试类 Bash 占比，前者用于排除探索时长被误读为能力差异，中两者直接对应题目所说的更谨慎地定位还是过度修改。

## 六、验收清单

阶段 4 结束后逐条核对，全为是才进入阶段 5。

1. 每个首轮 episode 都有修改前后的测试结果、补丁与原始流。
2. 每个分支点的五个克隆快照哈希完全相等，且该断言记录在产物里。
3. 五份二轮提示词渲染后只差一行，脚本断言通过。
4. 每个条件的失败文本与单一来源文件逐字节相同。
5. 三种结局码各至少出现一次。
6. 篡改与空改动两条异常路径被假模型触发并正确处理。
7. 报告生成幂等，删掉产物重跑后表与图的哈希一致。
8. 中断续跑通过，中止后重启无 episode 重跑，总数不变。
9. 校准表就位，每个任务的首轮失败率落在两成到八成之间，越界任务列入重造名单。
10. 总时长与总成本已记录，并据此给出全量预算。

## 七、风险

| 风险 | 对策 |
|---|---|
| 首轮失败率偏离预期 | 阶段 4 量出真值，按预注册规则补造或重造任务，不削减条件 |
| 二轮样本量不足 | 主结论以风险差与区间为主，p 值为辅，且在看结果前写下 |
| 服务端模型漂移 | 同一任务的五个分支连续执行，条件顺序用固定种子打乱，记录时间戳事后检查 |
| 条件长度混淆 | 五条件内无法消除，改为预注册披露，用正交对比而非五组两两比较 |
| 两臂系统提示规模不同 | 两臂工具集不同导致输入规模相差约一倍二成，报告中不得声称两臂只差一个权限 |
| 隐藏测试泄漏 | 隐藏测试只经公开接口，不得触碰下划线开头的名字 |
| 网络路径变更 | 全部调用打同一个远端端点，跑批前后各确认一次代理模式 |
